## 2. Reproduction & Understanding
*   **Responsive Contract**: The navigation should be accessible and visually balanced across all viewports. The `.navbar-brand` logo should sit on the left, and the `.nav-link` items should sit on the right, collapsing or shrinking as necessary to fit small viewports (320px - 767px) without forcing a horizontal document scroll.
*   **Failure Threshold**: When testing widths below ~680px (specifically 320px, 375px, 430px), a significant page-level horizontal overflow was reproduced.
*   **Observation**: The navigation bar exceeded the viewport width on mobile sizes.

## 3. Root Cause Diagnosis
*   **Root Cause**: The `.navbar-brand` element inside `TheHeader.vue` had a rigid scoped CSS rule `min-width: 450px`.
*   **Causal Chain**: 
    1. Root Cause: `min-width: 450px` injected into `<style scoped>` of `TheHeader.vue`.
    2. Layout Constraint: The `nav` flex-child refused to shrink below 450px regardless of the viewport width.
    3. Parent Overflow: The combined width of `.navbar-brand` (450px) + navigation links (~220px) + container padding forced a minimum rigid width of ~680px.
    4. Observed Mobile Failure: A horizontal scrollbar appeared on any viewport under 680px (e.g., 320px, 375px).

## 4. Plan & Rationale
*   **Proposed Repair**: Remove the deceptive `min-width: 450px` rule from `.navbar-brand`. 
*   **Rationale**: The `min-width` constraint is structurally invalid for a mobile-first environment. By removing it, `.navbar-brand` reverts to intrinsic text sizing (~60px). The flex container (`.container`) will then naturally fit the remaining items within a ~280px total width, solving the overflow at 320px without adding brittle media queries or resorting to `overflow-x: hidden`.
*   **Blast Radius**: Zero cross-component blast radius since the CSS rule was scoped directly to `TheHeader.vue`.
